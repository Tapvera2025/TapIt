# People Frontend Completion — Steps 0–9

> **For agentic workers:** Implement the tasks in order, review each vertical slice, and use the registered server routes and response types as the source of truth. A screen is complete only when its real authorized route, loading/error states, and browser test work. Do not turn a plan-only endpoint or a placeholder service into an active control.

**Goal:** Finish the People frontend for the Step 0–9 backend: employee self-service, a useful workforce workspace, and a safe payroll workflow. The visual language should be calm and compact: one readable monthly calendar, purposeful charts, and short motion that clarifies state changes.

**Scope:** React client work for live status, attendance, shifts, holidays, biometric administration, leave/WFH, corrections, breaks, and payroll, plus the small API/registry changes required to make those screens truthful. Keep the existing identity, organization, access, and audit screens working. Do not expand this plan into the PRD's sales, projects, accounting, performance, or general reporting modules.

**Starting point (28 September):** The backend modules through migration `0064_payroll.sql` exist. The client has an existing company shell, design tokens, simple SVG charts, an employee break view, a breach list, and three thin payroll pages. It has no People calendar, live board, or complete payroll management UI. `CompanyWorkspace` dispatches on path strings and uses `accountType` to choose whole sections; the non-admin fallback renders `EmployeeBreakView` for unrelated routes. The break and payroll pages call raw `fetch`, while authenticated company requests use `identityRequest` and receive `{ success, data }`. There are no client component tests. The Vite `/api` proxy lacks `ws: true`. A registered `POST /api/status/punch`, shift-request create/list, correction queue/reject, manager acknowledgement list, and settings routes are not present in this checkout. Treat the reported completion of Step 9 as sequencing context; verify each UI-facing contract before building on it.

## Product structure and design rules

| Audience | Primary destination | Main jobs |
|---|---|---|
| Employee | Today | See the attributed work day, make permitted punch moves when G1 is live, check break allowance, request leave/WFH or correction, open own calendar and published slips |
| Team lead | Team | Read the scoped live board and team calendar, acknowledge leave, inspect a person's day; no correction or pay decision just because they manage a team |
| HR / workforce reviewer | Workforce | Resolve leave, corrections and breaches; manage shifts, holidays, break policies and devices within granted scope |
| Payroll manager | Payroll | Configure salary and statutory inputs, freeze/review/publish a run, investigate drift, revise a published slip and view the register |

- Keep one **route manifest** for screen path, label, section, required action, enabled module, breadcrumb, and audited availability (`ready | read-only | backend-gated`) with optional gate ID (`G1`, `G3`, `G8`, `G9`, `G14`). The sidebar, page header, disabled-action explanation and active state read it. Bootstrap capabilities decide coarse navigation only. Authorization remains on the server; hiding a menu item is only a presentation rule.
- Preserve the current light/dark palette and typography. Use neutral surfaces, one warm accent for actions and selected dates, semantic status colors with text/icons, and tabular numerals for time and money. No gradient on every card. Keep dense data in tables and detail drawers rather than expanding the dashboard into many tiles.
- Use a maximum two-column page layout: primary work surface plus an optional 20–24rem detail panel on desktop; the panel becomes a full-screen sheet on narrow screens. At 320px, every action remains reachable and tabular data has a deliberate compact/list mode.
- Motion: 120–220ms opacity/transform for drawers, route content, selected dates and chart focus; use no layout-wide movement, autoplay, bouncing counters or payroll amount count-up. Suppress nonessential animation under `prefers-reduced-motion`. A state change is also conveyed by text and focus, never by animation alone.
- Dates are `DateOnly` in the organization's timezone. Add timezone to the identity bootstrap contract if absent. Never parse a work date as browser-local midnight; display overnight intervals with a next-day marker while keeping them on their attributed `work_date`. Format money from integer paise for display only; the client never recalculates payroll.

The API work in this table is a narrow prerequisite, not a second backend rewrite. Register new actions/routes in `team-docs/security/AUTHORIZATION.md`, extract the registry, add subject loaders and scope tests, then return to the screen that needs them. Where a gate depends on HR or document-owner decisions, ship the readable surface and a clearly disabled action with its reason.

**Two levels of capability:** Identity bootstrap supplies only coarse screen eligibility. After a server-scoped list or detail read, each visible resource DTO supplies server-computed `allowedActions` (or equivalent typed booleans) for its row and detail drawer: e.g. `{ confirm: true, waive: true, explain: false }` for a breach. Compute these with the actual subject, current status, scope and separation-of-duties constraints, including A1; refresh after a mutation or `permissions:changed`. The client never reconstructs team, department, pool or self-review rules. Scope-filter the list **before** adding affordances: an unauthorized record is absent, not returned with all actions false. Buttons remain subject to authorization again at mutation time.

## Calendar and chart contracts

**One shared calendar, three contexts.** `PeopleCalendar` is a 7-column month grid of at most 42 cells on desktop and a compact week strip plus chronological list on mobile. Attendance, leave and holidays supply dated layers; shifts supply a small time label. A cell has one primary status label and at most two secondary markers (WFH, correction/review, or shift exception). Half days use a split marker. A selected day opens the detail panel with stored status, minutes, shift source, event evidence, leave/holiday overlay and correction provenance. Use the server's stored day facts; do not recompute status precedence in React. Missing day, open day, recalculating day and no assigned shift are visually distinct from absence. The month is bounded to the visible range; spillover cells are dimmed and are fetched only within the attendance API's 92-day ceiling. Month, person and view are URL state; keyboard arrows/Home/End navigate dates, and the selected date is announced. A month change preserves focus and uses no sliding 42-cell animation.

**Charts are questions, not decorations.** Each chart has a title, date range, denominator, “as of” time, textual summary, legend, accessible data table and a click-through to the underlying filtered view. Use existing SVG primitives for compact charts; add one measured chart dependency only if the interaction or density warrants it. All chart data is scope-filtered and aggregated on the server. Do not derive an HR chart by downloading 2,000 employees × 31 raw attendance rows into the browser.

| Chart | Question and interaction | Source / definition |
|---|---|---|
| Live distribution | Segmented horizontal bar: how many are working, on break, finished, not yet due, overdue, on leave or holiday? Select a segment to filter the board | Existing `/api/attendance/live.groups`; show `asOf` and connection state |
| Attendance trend | Stacked daily columns: how did present, paid leave, unpaid leave, absent and unevaluated units change? Toggle absolute units / share and open a day | New bounded, scope-safe attendance aggregate; calculated units only, with eligible-person/day denominator and unevaluated shown separately |
| Exception trend | Small-multiple lines: are late, early-exit and overtime minutes or review items changing? Brush at most 92 days, click a point to filtered daily view; do not put unlike units on one axis | Same bounded attendance aggregate, distinct metrics and zero/missing semantics; no inference from raw punch count |
| Leave coverage | Compact occupancy heat strip: which upcoming dates have approved leave/WFH in the visible team? Select a date to see scoped requests | Existing leave calendar for a bounded month; do not expose another team's names |
| Payroll variance | Diverging ranked bars with a frozen-basis breakdown: which employees differ most from their previous **published** month and why? Select a bar to open the slip | New paged run aggregate or bounded server-side top-N; show signed integer-paise delta, exclude draft history from previous-net lookup |

The aggregate endpoint must return metric definitions, numerator/denominator, UTC `asOf`, organization timezone and a complete ordered date series; it must label `unavailable` rather than fabricating zeros for missing or stale calculations. Finance totals are returned only under `payroll:manage`. Add direct authorization tests for own/team/department/all-people scopes and a different tenant.

Preserve the `{ success, data }` envelope, one refresh retry, typed error codes, abortable reads and an authenticated document-download path. Use a small in-memory keyed query cache with stale times, request deduplication and mutation invalidation; do not install a broad state framework for server data. Each request captures the epoch and principal/org pair at start and discards its response if either changed before completion, even if network abort came too late. Access-token refresh reconnects the socket with the new token and revalidates bootstrap identity before reusing cached data.
